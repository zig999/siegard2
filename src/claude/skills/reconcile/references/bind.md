# The bind

Read at step 5, before running `--bind-record`.

## Second reading, never skipped

Where the record reads a pair `nowhere`, run `trace.py --stage-release <target-source-root>
<specification-root> siegard-reconcile/<slug>.md <new workspace>`, then one conformance subagent
per printed pack, each saved there by `--save-return`. The bind releases what it confirms;
skipped, every such release falls to the person.

## What lands

The record is read the same way an implementation record is, and the whole of it is refused
before anything is written where its form is wrong — a node this specification does not hold, or
a file that is not there. That is a defect in what you wrote, never the judgment's answer.

- `--workspace` names the staging's own: the bind refuses a file or a node that moved since the
  staging read it, because it stamps what the judges read.
- What lands is the union: a file an earlier bind put on a node and this record does not name
  stays bound.
- **Where a node carries a finding, that node is not bound, and the nodes that cleared still are.**
  The join is structural: a pair the judgment refused is under no `encoded_at`, and the bind reads
  only the pairs that are, so it writes exactly the cleared set however anyone runs it.

## `--replace` and the release

**This skill never passes `--replace`.** Where the person says a fact moved out of a file rather
than into an additional one, the report hands that invocation ready to paste and stops.

A node whose fact left part of its ground, with nothing found against it, is bound on the files
that still hold it. A file read `nowhere` that the second reading did not confirm is a release the
bind's receipt hands with its `--release ... --node` invocation ready, and the report relays it as
the person's decision. It drops that pair alone; a `--replace` naming the files to keep is the
loss that invocation exists to prevent.

## What it rechecks

The bind recomputes every `pairs_omitted` claim at this moment, both halves: the binding still
computes at the file's content, and the corpus holds nothing open against the pair. It recomputes
every reproduction under `rewritten` the same way. A claim that stopped holding refuses the record
whole — a file moved between staging and binding, which broke the committed-tree premise — and
the route is a fresh invocation under a new slug, never a bind around the pair.

## What it is not

It is not a claim that the set is reconciled. A cleared node's binding rests on the judgment that
cleared it and on nothing else in the record; a node with a finding against it stays exactly as it
stood.

**What `--check` says about that node afterwards is a different question, and often the answer is
nothing.** Drift is computed from the bindings:

- where the pair was bound before, its old digest still reports, and the drift report is honest
  about it;
- where it was not — a node the judgment opened as a candidate, bound to a sibling file and not to
  this one — there is no digest to disagree with, and there never will be;
- a later bind that stamps the very content the finding was read in removes the only digest that
  did.

`trace.py --owed <target-source-root>` reads the records back and says which state each finding is
in; the count `--check` reports is not that number. Holding the cleared bindings back would have
thrown away every reading that succeeded, and the next invocation would re-judge files nobody
touched.

## The receipt

**Read the bind's receipt and carry it into the report.** It names:

- the nodes it did not write — the one place the partial shape of the act is stated as it happens;
- what it certified — each node now decided by a test, with the step and the proof it pinned;
- any certification an earlier bind held that this one released because the proof's text changed.

The fold already said which certifications did not hold and why, in the record's `notes`; the bind
says which ones landed.
