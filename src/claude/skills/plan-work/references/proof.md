# The proof increment

Read when the person names facts a finite test decides, held by delivered code and proven by none.

A certification the coverage auditor refused with `remainder: testable` names the assertion that
would close it. «A finite test is preferred to a reading, and to a registry step's decision,
wherever one exists» (SPEC-004 R10): a node left decided by a reading where a test could decide it
is owed that test, however long ago its implementation was delivered. This route owes it a task.

## What the invocation names

**The person names this in the invocation; it is never inferred.** Per fact, four things, all the
person's:

- the node, by identity;
- the assertion, verbatim, as the record's `remainder_why` states it;
- the record that stated it, by path under `siegard-reconcile/`;
- the file or files the node is bound to where its fact is held.

`trace.py --owed` prints these per node, and its closing line hands this invocation ready to fill.
Which facts are worth a test is the person's: this route takes the ones named and proposes none.

## Two stops

- **Every named file must be one the trace binds the node to:**

  ```
  python3 -B ${CLAUDE_PLUGIN_ROOT}/bin/trace.py --encodes <target-source-root> <file> [<file> ...]
  ```

  A node the output does not list for a named file is a fact that does not stand there: the route
  is `/reconcile` over that file.
- **The record must carry the node with `remainder: testable`.** An `untestable` remainder is one
  no finite test closes, and a task over it would write the partial test R12 forbids.

## What does not run

**The survey and the decomposition do not run**, and nothing reads source: the implementation
stands, the trace says where, and the assertion states what the task owes. `intake/` holds the
invocation and nothing else — per fact the node, the assertion verbatim, the record's path and the
files.

The decider reads `intake/` as the one place a fact may already be stated, and an assertion is a
test's condition over a fact the node already holds, never a new fact. So **a decider return whose
edit writes into a node a fact it found only in an assertion under `intake/` is not written**: the
task stays out of the plan, and the report hands two doors — `/analyse` over the node, with the
assertion as its material, or the return written as it stands — recommending the first, with its
criterion and both facts — «A recommendation names the door, the criterion, the deciding fact and
the reversing fact» (SPEC-006 R2). The criterion is `rule violated`; the deciding fact is the
return's edit, quoted beside the `intake/` path it cites; the reversing fact would be a node that
already held the fact before this invocation. Say it to the person in plain words; the name is for
the orchestration log.

## The tasks

**One task per fact, under one epic of their own.** The binder runs per task as step 4 runs it,
handed as its candidate set the node **and every node that names it** — read, never recalled, from:

```
python3 -B ${CLAUDE_PLUGIN_ROOT}/bin/spec.py --impact <node> <specification-root>
```

A contract or a rule answering the same case is where an assertion contradicts the specification,
and a binder handed the one node alone cannot see it. Every note routes as `references/notes.md`
states; a `BLOCKING, from the specification —` note here is the standing stop for that fact,
settled by a person before any test is written. A binder that returns no `implements` for the node
is a stop for that fact alone, reported with the binder's reason.

The task you write carries:

- `implements`: the node, and nothing else;
- one criterion: the assertion, verbatim — falsifiable, because an auditor wrote it as the one thing
  a test must fail over;
- `stands`: the files, exactly as the invocation named them and `--encodes` confirmed them;
- `sources`: the scope under `intake/`;
- no `produces`: a proof task builds no substrate, and the schema refuses the two together.

The epic's `covers` is the tasks' nodes. A closed work root takes nothing, so these facts name a
new slug. The tasks go to `/implement-task`, which reads `stands` and writes the proof alone; the
review that reads it certifies each node. Say in the report that this was a proof increment and
which steps did not run, and carry the `--encodes` and `--impact` outputs verbatim.
